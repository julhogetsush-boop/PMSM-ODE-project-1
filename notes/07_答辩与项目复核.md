# 答辩、版本复现与项目记录

## 按真实 commit 完成 Tutorial 4

1. 本人先运行 `python code/run_all.py`，核对生成图、数据和报告段落。
2. 在团队仓库形成真实提交，记录完整 commit SHA；不要将本次打包当作此前四周的个人 Git 历史。
3. 在另一个 checkout 或仓库副本中检出该 commit。操作前保存自己的未提交工作，避免覆盖修改。
4. 从该版本根目录按 README 安装依赖，运行 `python code/week4_reproduction.py --require-clean-commit --expected-commit YOUR_REAL_COMMIT`。
5. 保存 `results/week4_reproduction.json` 与 `results/week4_reproduction_line.txt`。严格模式会验证 HEAD、源码跟踪和运行前的干净状态；SHA256 补充记录文件内容，不替代 commit。
6. 实际复核者填写下面的记录，核对一致数字后按课程要求保存共识和提交记录。

复现脚本将报告草稿中的原始值放在 `report/report_claims.json`，实际重新计算后比对 3 位有效数字。若参数或代码改变造成不匹配，应先审查结果和更新报告中的主张，再同步 claims 文件；不能只改判据来掩盖错误。

## 白板答辩练习

| 提问 | 应能独立推导/解释 |
|---|---|
| 这里为什么只有两个状态？ | 速度外部给定；不是完整机械加速模型 |
| 反电动势项和耦合项怎样核对？ | d-q 统一符号约定；逐项检查 V 与 A/s |
| 常系数模型需要数值算法吗？ | 单条轨迹可用矩阵指数；本项目用其校准方法和稳定性 |
| 平衡点如何计算并检查？ | 解 Ay*=-b；代回 f，并区别导数零和电流零 |
| 如何证明扰动衰减？ | x=D(y-y*)；反对称耦合在 x^TBx 中消去 |
| Euler 复特征值步长界？ | 展开 (1-αh)²+β²h²≤1 得 2α/(α²+β²) |
| 隐式 Euler 稳定域？ | |1-z|≥1，为 z=1 圆盘外部；左半平面全包含 |
| 局部 O(h²) 为何只有一阶？ | T/h 次误差累积与 Lipschitz 传播；说明 LTE 的定义 |
| 图上4.038和复现4.04是否矛盾？ | 三位小数和三位有效数字不同；原始值一致 |
| Newton 首步一轮意味着什么？ | 仿射残差一次线性修正；未验证非线性收敛阶 |
| 自适应 E≤1 为什么全局误差仍更大？ | 局部缺陷估计与跨步骤传播不同；用 oracle 单独测全局误差 |
| 选择更快方法的证据是什么？ | 同一误差上限、明确计数；这里比较 RHS，不替代总运行时间 |

## Pair review 记录模板

Tutorial 要求配对团队互换近最终草稿，给一个优点与一项具体建议，反馈保留在两队间。下面由实际审阅者填写：

- 被审团队/草稿版本：______。
- 一个具体优点（关联公式/图/表）：______。
- 一个具体建议（问题、位置、如何验证修复）：______。
- 收到的建议、是否采用及理由：______。
- 修改后的文件/commit：______。

不要把自查意见冒充已收到的外部互评。Seminar 2 的纸质 peer-review 和数据库记录需由每位成员本人完成。

## 可编辑的项目记录草稿

**Consensus：** 在相同教学参数下，复现 RK4 endpoint 阶数为4.04（3位有效数字），并记录脚本、命令、环境和源码哈希。正式记录补入全体实际复现者和真实 commit；团队参数更换后重新复现。

**Milestone：** 完成数字复现脚本、数学公式复核、共同精度上限的成本实验和逐项检查。下一步合并团队最终参数与报告，补齐真实 ICS、展示 PDF 及提交证据。当前限制是这些团队材料未提供。

**Wrap-up 可改写句：** 本项目使我认识到稳定、准确与可复现分别需要证据；我会在 Project 2 继续先构造独立参考，再报告误差和版本。

以上为文稿草案，没有发送论坛/数据库。成员应依据真实经历修改，个人贡献不能只引用团队 consensus。
