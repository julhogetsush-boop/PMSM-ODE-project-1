## 4. 由你上传 GitHub

建议将本包作为一个独立仓库的根目录，或放入现有团队仓库的 `weeks1-2/` 子目录。这样不会混入原始教材和历史报告。本次不替你上传，也不创建虚假的历史提交。

**用 GitHub Desktop：** 将本包目录加入仓库，检查 Changes，写一个符合真实工作的提交说明，然后由你 Publish/Push。已有团队仓库时先同步团队更改，再复制本包内容到约定子目录；不要用新文件覆盖队友的同名文件。

**用网页上传：** 在你选择的仓库里使用 Add file → Upload files，上传本包中的源文件、notes 和选定的阶段定稿图。网页上传不会替你遵守 `.gitignore`，所以不要拖入 `.venv`、`__pycache__` 或原始学习资料目录。ZIP 便于搬运；若只上传 ZIP，GitHub 将不能直接展示里面的 notes，建议解压后上传。

**使用 Git 的可选命令：** 在你确认这是一个新建、尚无 Git 历史的本包文件夹后执行：

```text
git init
git add README.md requirements.txt parameters.json .gitignore AI_Transparency_Log.md code notes figures results/README.md
git commit -m "Add verified Week 1-2 PMSM notes and numerical experiments"
```

随后在你自己的 GitHub 仓库页面复制真实远程地址并按页面指引连接、推送。此处不填假仓库 URL，不代设作者，不伪造 Week 1 / Week 2 的时间戳。

本包保留的 10 张 PNG 是便于 GitHub 阅读的阶段定稿图；这符合 git quickref 中允许保留选定最终图的例外。原始 CSV/JSON、虚拟环境与构建缓存由 `.gitignore` 排除，需要时运行脚本再生成。若团队要求仓库只存源码，可继续忽略 PNG，但线上结果页的图片需要另行安排。
